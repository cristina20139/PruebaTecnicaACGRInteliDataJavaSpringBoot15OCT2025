📁 Estructura de Directorios (completa)

Listado jerarquizado de todos los paquetes y archivos que me enviaste. Cada fila corresponde a un elemento (paquete o archivo) con su tipo, funcionalidad técnica y observaciones.

📂 Elemento 🧩 Tipo ⚙️ Funcionalidad técnica 🗒️ Observaciones
📁com.intelidata.acgr.pruebatecnica Paquete raíz Contenedor principal de la aplicación; punto de escaneo de componentes de Spring. Contiene subpaquetes: adapter, application, domain, infrastructure.
📄SpringbootLambdaApplication.java Clase principal Arranca la aplicación Spring Boot (`SpringApplication.run(...)`). Punto de entrada; activa ComponentScan y auto-configuración.
📁domain Paquete Contiene el modelo de dominio (entidades puras). Independiente de frameworks (sin anotaciones JPA aquí).
📄User.java Entidad de dominio Modelo de usuario con id, name, email; equals/hashCode definidos. Usado por servicios de aplicación y adaptadores; serializable para JSON.
📁application Paquete Capa de aplicación: casos de uso y puertos (interfaces). Orquesta la lógica sin depender de la infraestructura concreta.
📁application.port.output Paquete (puertos de salida) Define contratos que la infraestructura debe implementar (repositorios). Sigue patrón Ports & Adapters.
📄UserReadRepositoryPort.java Interfaz (Read port) Define método findAll() para listar usuarios desde el exterior. Separación de lectura/escritura (CQRS simple).
📄UserWriteRepositoryPort.java Interfaz (Write port) Define métodos save(User) y existsByEmail(String). Usado por servicios de aplicación para persistir y validar duplicados.
📁application.service Paquete (servicios) Implementa casos de uso: crear y listar usuarios. Inyecta puertos para acceder a la infraestructura.
📄CreateUserService.java Servicio de aplicación Valida email no nulo / no duplicado y delega save al puerto de escritura. Lanza IllegalArgumentException o IllegalStateException("EMAIL_DUPLICATE").
📄ListUsersService.java Servicio de aplicación Invoca UserReadRepositoryPort.findAll() y devuelve lista de usuarios. No aplica filtros ni paginación (podría extenderse).
📁adapter.persistence Paquete (adaptador de persistencia) Contiene entidades JPA, repositorios Spring Data y adaptadores que implementan puertos. Implementa UserWriteRepositoryPort / UserReadRepositoryPort.
📄UserEntity.java Entidad JPA Anotada con @Entity, mapea tabla users y columna única email. Contiene id, name, email; getters/setters estándar.
📄SpringDataUserRepository.java Interfaz JPA Repository Extiende JpaRepository y define existsByEmail, findByEmail. Spring Data genera implementación en runtime.
📄JpaUserRepositoryAdapter.java Adaptador (implementa puertos) Implementa UserReadRepositoryPort y UserWriteRepositoryPort; mapea entre User y UserEntity. Convierte entidades a modelos de dominio y delega llamadas a SpringDataUserRepository.
📁adapter.rest Paquete (adaptadores REST) Controladores que exponen la API HTTP (comandos y queries). Se divide en subpaquetes: command, query, auth.
📁adapter.rest.auth Subpaquete Controlador público para autenticación y generación de tokens JWT. Endpoint: POST /auth/login.
📄AuthController.java Controller REST Recibe email (login simulado) y retorna JWT usando JwtUtil.generateToken(email). No valida contraseña en esta demo; ideal para pruebas.
📁adapter.rest.command Subpaquete Controladores de comando que modifican estado (ej. crear usuario). Exponen endpoints POST/PUT/DELETE en futuro.
📄UserCommandController.java Controller REST (Command) Endpoint POST /users que recibe User y llama a CreateUserService.createUser(). Manejo de errores mapeado a códigos HTTP (409, 400, 500).
📁adapter.rest.query Subpaquete Controladores de consulta (solo lectura). Separación Command vs Query (CQRS simplificado).
📄UserQueryController.java Controller REST (Query) Endpoint GET /users que devuelve lista mediante ListUsersService.listAll(). Retorna lista de objetos de dominio User.
📁infrastructure Paquete Configuraciones, seguridad, excepciones y recursos de infraestructura. Incluye config, security, exception, etc.
📁infrastructure.config Subpaquete Beans de configuración y inicializadores de datos. Ej.: SwaggerConfig, DataInitializer.
📄DataInitializer.java Bean (CommandLineRunner) Precarga usuarios si no existen (usa UserWriteRepositoryPort). Insertar datos de prueba en H2 al arrancar.
📄SwaggerConfig.java Bean OpenAPI Configura metadatos OpenAPI y esquema de seguridad Bearer (JWT) para Swagger UI. Define dos beans OpenAPI (uno primario con seguridad).
📁infrastructure.exception Subpaquete Manejadores globales para transformar excepciones en respuestas HTTP coherentes. Centraliza códigos 400, 409 y 500.
📄GlobalExceptionHandler.java ControllerAdvice Intercepta IllegalStateException, IllegalArgumentException, y genéricas. Retorna JSON con clave "error" y mensajes adecuados.
📁infrastructure.security Subpaquete Módulo de autenticación y autorización (JWT + Spring Security). Incluye utilidades, filtros y configuración del resource server.
📄JwtUtil.java Componente Genera y valida tokens JWT con clave simétrica (JJWT). Métodos: generateToken, validateToken, extractEmail.
📄JwtDecoderConfig.java Bean Provee JwtDecoder (Nimbus) configurado con la misma clave HMAC SHA-256. Asegura compatibilidad con Spring Security resource server.
📄JwtAuthFilter.java Filtro HTTP Verifica encabezado Authorization: Bearer <token> y valida token via JwtUtil. Extiende OncePerRequestFilter; devuelve 401 si token inválido.
📄SecurityConfig.java Configuración de seguridad Define SecurityFilterChain, rutas públicas (/auth/**) y protegidas (/users/**); session stateless; integra JwtDecoder. Usa oauth2ResourceServer().jwt() para validación.
📁resources Directorio Contiene propiedades, scripts SQL, y recursos estáticos. Ej.: application.yml, posibles data.sql.
📁test Directorio de pruebas Clases de test para verificar arranque y comportamiento (JUnit). Incluye clase test nombrada en tu repo (p. ej. ProyectoAcgrBbvaCambioDivisasApplicationTests si existe).
📄ProyectoAcgrBbvaCambioDivisasApplicationTests.java Clase de test (ejemplo) Comprueba que el contexto de Spring arranca correctamente. Nombre referenciado en conversaciones previas; reemplazar por tus tests reales.
