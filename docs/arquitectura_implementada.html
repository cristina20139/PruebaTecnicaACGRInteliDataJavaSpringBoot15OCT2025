Arquitecturas Implementadas en el Proyecto Spring Boot

El proyecto com.intelidata.acgr.pruebatecnica implementa múltiples enfoques arquitectónicos modernos que garantizan mantenibilidad, escalabilidad y seguridad. A continuación se describen con detalle técnico.

1. Arquitectura Hexagonal (Ports & Adapters)

Esta arquitectura divide el sistema en capas que se comunican mediante interfaces (“puertos”). Los adaptadores externos (REST, seguridad, base de datos) interactúan con el núcleo de la aplicación sin acoplarla a frameworks específicos.

  • Adaptadores de Entrada: Controladores REST (AuthController.java).
  • Adaptadores de Infraestructura: Seguridad JWT (JwtUtil.java, SecurityConfig.java).
  • Núcleo: Clases de dominio y servicios (en este caso, la lógica de autenticación).
package com.intelidata.acgr.pruebatecnica.adapter.rest.auth;

@RestController
@RequestMapping("/auth")
public class AuthController {

    private final JwtUtil jwtUtil;

    public AuthController(JwtUtil jwtUtil) {
        this.jwtUtil = jwtUtil;
    }

    @PostMapping("/login")
    public ResponseEntity<Map<String, String>> login(@RequestBody UserDTO user) {
        // Lógica central delegada al núcleo de negocio
        String token = jwtUtil.generateToken(user.getUsername());
        return ResponseEntity.ok(Map.of("token", token));
    }
}

Ventajas técnicas:

  • Separación total entre lógica de negocio e infraestructura.
  • Facilita pruebas unitarias y mock de dependencias.
  • Posible evolución hacia microservicios sin reescribir el core.

2. Arquitectura Basada en Servicios (RESTful API)

La aplicación expone endpoints HTTP siguiendo los principios REST, usando JSON como formato de intercambio.

POST /auth/login
Entrada 
{ "username": "acgarzon", "password": "12345" }
Salida 
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6..." }

Configuración de endpoints:

http.authorizeHttpRequests(auth -> auth
    .requestMatchers("/auth/**").permitAll()
    .requestMatchers("/users/**").authenticated()
    .anyRequest().permitAll());

3. Arquitectura de Seguridad JWT (Token-Based Authentication)

El sistema usa JSON Web Tokens para autenticar usuarios sin mantener estado en el servidor.

public class JwtUtil {

    private final String SECRET_KEY = "MiClaveSecreta12345";

    public String generateToken(String username) {
        return Jwts.builder()
                .setSubject(username)
                .setIssuedAt(new Date())
                .setExpiration(new Date(System.currentTimeMillis() + 3600000)) // 1 hora
                .signWith(SignatureAlgorithm.HS256, SECRET_KEY)
                .compact();
    }

    public boolean validateToken(String token) {
        try {
            Jwts.parser().setSigningKey(SECRET_KEY).parseClaimsJws(token);
            return true;
        } catch (Exception e) {
            return false;
        }
    }
}
  • El token viaja en la cabecera HTTP: Authorization: Bearer <token>
  • Valida integridad y expiración sin requerir base de datos.
  • Ideal para despliegues sin sesión (Lambda, Kubernetes).

4. Arquitectura Monolítica Modular

Aunque usa principios limpios, el proyecto se ejecuta como una única aplicación Spring Boot que agrupa los módulos internos en paquetes bien organizados.

com.intelidata.acgr.pruebatecnica
 ┣ adapter.rest.auth → Controladores REST
 ┣ infrastructure.security → Seguridad y JWT
 ┣ SpringbootLambdaApplication → Clase principal

Ventajas: simplicidad de despliegue, facilidad de mantenimiento y posibilidad de refactorización hacia microservicios.

5. Arquitectura Stateless

La sesión del usuario no se guarda en el servidor. Cada solicitud contiene su propio token JWT.

http.sessionManagement(session ->
    session.sessionCreationPolicy(SessionCreationPolicy.STATELESS));

Esto es esencial para entornos serverless o contenedorizados, como AWS Lambda o EKS.
